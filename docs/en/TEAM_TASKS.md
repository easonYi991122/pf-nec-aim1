# Team task cards: T-2 through T-6

Version: NX-H4c-v1. These are bounded menus and delivery contracts; the controller assigns named owners, freezes appendices and approves budgets. The controller approves research and real runs; teammates execute on authorized hosts. Using patient-level data outside registered hosts requires prior confirmation by the user and PI under the DUA; a task card or default path is not transfer authorization. No gain, non-identifiability or failed linkage are acceptable null deliverables.

Sources: approved plan v3 §II.8, §III D1/D3 and DEC-019. Internal originals are not shipped; task boundaries are specified here. Task T-3 differs from the historical attribution module T3. Code use is documented below; see [TASKS](TASKS.md) for existing contracts and [EXCLUDED](EXCLUDED.md) for exclusions.

## Start here: terms used in the cards

The project aims to identify neonates at risk of NEC (necrotizing enterocolitis) after heart surgery, using information already available at prediction time. “Passing” a task means research acceptance, not approval for clinical use. See [GLOSSARY](GLOSSARY.md) for other abbreviations.

|Term|Meaning in these cards|
|---|---|
|D5-safe|The 604-column registry feature bank masked for availability on each day; the name is not a window length.|
|GAIN50|Keep the top 50 columns ranked by tree gain within the current training subset; validation and test labels never select columns.|
|PI72-CLEAN|The local cleaned row-selection, daily-label and evaluation contract; neither the recovered original paper design nor a deployment population.|
|r1–5 / r0–4|Previously used repeat IDs for PI72-CLEAN and Task A/B, respectively; each names 5 splits, not the same random splits or new patients.|
|POD / yB30|POD means postoperative day, with POD0 the surgery day; yB30 indicates first recorded NEC within 30 days after a fixed prediction time.|
|MDD|Minimum detectable difference; the AUROC gain gate here is 0.01, and smaller differences are not interpreted as progress.|
|Simultaneous interval|An uncertainty interval providing joint coverage across the full predeclared comparison family, avoiding selection of the most favourable individual interval.|

## Shared acceptance gates

- Split history: PI72-CLEAN r1–5 and Task A/B r0–4 have already been seen. New seeds or extension from 3 to 5 repeats do not restore independence. Label all new results “replication / development evidence”. D1 creates no new holdout from existing data; it records only an intent to isolate future new data, with access, training and selection logs sealed before the controller freezes use and evaluation.

- Statistical gate: pair each difference only within the same task, risk set, label, timing and split. Require 5 complete repeats, mean paired AUROC gain at least 0.01 and a simultaneous 95% lower bound above 0 for the full declared family; at least 1990 of 2000 stratified hospitalization bootstrap draws must be jointly valid. A 3-repeat run is a screen only. Weight repeats equally and share hospitalization multiplicities across repeats and models; missing arms, single classes or inadequate support yield incomplete/null, without shrinking the family or redrawing.

- Clinical alert gate: before real scoring, the controller and PI must sign a common appendix specifying the primary alert level, minimum clinical detection gain, cooldown, missing-day handling, warnable-case denominator and event deduplication. These clinical values are currently unavailable, so this gate is BLOCKED; neither the AUROC 0.01 threshold nor historical negative-day 5% FPR may substitute. Without the appendix, deliver code / synthetic evidence only and make no clinical-pass claim.

- Separate alert reports: retrospective capacity curves ranking all days, and policies with thresholds set on inner OOF predictions and applied externally. Both report actual alerts per 100 at-risk days, deduplicated case detection, PPV, alerts per 1 detected case, missed cases and denominators, plus paired detection differences at equal burden. Fit thresholds and calibrators without outer-test data. Sampling and outcome selection in PI72-CLEAN / formal prevent extrapolation to deployment burden.

- Timing gate: apply D5-safe masking to each historical day before constructing windows; surgery information is unavailable preoperatively and ICU / first 2-hour information uses the frozen availability gates. Resolve any T-5 timing issue affecting an intended input before using it; “unconfirmed” does not mean “leakage”. Disclose late_era truncation, unresolved hospitalization-to-person linkage and the distinction between the local clean contract and the manuscript scoring design.

- Resource gate: the caps below are new planning limits, not measured timings. Count retries, preprocessing, inference, occupied queue time and inner threshold fitting; forecast total use from the first planned fit and stop as incomplete if over budget, without reducing seeds / repeats / menus. Use 2 numerical threads per process, an 8 GiB RSS cap, a single GPU job and a 6 GiB GPU-memory cap; identical-configuration resumption also counts.

- T-2/T-3 share a preregistered contrast ledger: 4 T-2 contrasts plus 6 T-3 contrasts form a joint simultaneous family of 10. Share hospitalization sampling weights, but calculate each difference inside its own declared row set; never subtract AUROCs across risk sets. The controller must implement and blindly review stratum-mask support for this new family; do not relabel an old family. T-4 belongs to a separate Task B family.

## Shipped code and explicit gaps

`explore.team.sequence` provides fit / label-free apply packages for TCN, GRU and ORDERLESS_MLP from the D5-safe input bank, with neural interfaces restricted to training-pool GAIN50 w3/w7. The full D5SAFE neural path is not shipped: the frozen R4 channel cap and full-bank multi-day prohibition remain in force. `explore.team.sequence_m1` provides GAIN50 paths for TabM, GRU-D and CausalMS-CNN mechanisms; only the first two belong to the T-2 menu. Full D5SAFE does not enter M1, preserving inherited input / parameter caps. Under D3, PI10 remains an interpretation group only.

TabM requires installed `tabm==0.0.3` and `rtdl_num_embeddings==0.0.12`; missing or different versions fail explicitly without model substitution. Exported modules use the new [spec.json](../../src/explore/team/spec.json), leaving the final-model spec and harness unchanged. Synthetic entry point: `python -m pytest tests/test_team.py tests/test_team_sequence.py tests/test_team_m1.py -p no:cacheprovider --basetemp="$PF_RUN_DIR/team-tests"`.

See [TEAM_USAGE](TEAM_USAGE.md) for runnable synthetic calls and explanations of FeatureRows, FitContext, inner/refit/apply and exact label indexing, plus supplied configurations and selection / reference settings still requiring freeze.

Programming order: fit the current child ranking with `inputs.gain50(train_rows, train_labels, context)`; apply its returned selection to validation / apply rows with `inputs.selected_rows`; then use the runner’s `make_config`, `build_fit_package`, `fit_package`, `build_apply_package` and `apply_package` for one fit. Rerank on the outer-training pool at each outer refit; never reuse another child’s or an outer-test ranking.

Not shipped: historical full menus / job queues, automatic scheduling for these new cards, POD0–2 inner scoring and joint-family adapters, alert-policy execution, the new Task B training driver or real-data derivatives. The base sequence runner accepts an external inner scoring mask, but its PI72-CLEAN receipt still uses the inherited AUROC_post name; T-3 needs adapted row-set binding and receipt naming before claiming execution. The controller creates real-run requests after prerequisites are met; this package promises neither results nor promotion.
